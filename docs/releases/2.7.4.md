# OpenTurbine 2.7.4

N1 underspeed shutdown remains active alongside N1-based combustion-loss detection. If both are enabled, underspeed can cut fuel before the combustion-loss delay expires. Installations that deliberately use only the delayed N1 combustion-loss response can switch off the separate underspeed trip. N1 and N2 overspeed confirmation now requires fresh shaft readings across the confirmation window.

Saved startup sequences keep their existing checks and output actions. The Sequence page explains the evidence each check provides, and the running transition reports startup sequence completion. The guide clarifies startup temperature protection and the automatic relight attempt limit.

Cooldown honors recorded heat and releases only the outputs it controlled. The built-in N2 governor retains small pitch corrections and is kept in place when a configuration is opened in Controllers. Afterburner analog requests clear on signal loss, and EGT arming baseline averaging stays consistent. Automatic relight requires recovery evidence acquired within its attempt window and honors loss of the N1 firing permission.

The Cooldown card lets you select starter and oil independently. The fitted oil pump is enabled by default on new configurations. You can carry the last pump command into the next step. Holding START and STOP advances the active Cooldown step only.

Starter Spin starts its ramp or first assist pulse once the optional Starter Enable delay has elapsed. When assist ends, the ramp starts from the applied demand. If N1 reaches the pre-ignition target during a pulse, the next card inherits the applied demand. N1 loss during assist keeps it cancelled for that attempt.

Proportional **Set Starter** action cards show the previous target, estimated starting demand, and command rate in percentage points per second. Sequence flags overlapping ramps along fixed timing and leaves the starting demand open when it depends on a condition.

Hardware saves with analog TOT or TIT now pass boot validation using the configured analog input. If boot rejects the hardware configuration, the ECU keeps the hardware error visible.

Final Startup Checks offers optional minimum and maximum limits for numeric sensor checks, including a fitted battery-voltage input. The oil-pressure check can use the shared minimum or its own limits.

Final Startup Checks defaults to turning off the starter, its fitted enable output, and ignition energized by the startup sequence when the card exits. Saved option choices are retained.

Oil-pump calibration output times out if the wizard loses its connection. ESP32-S3 retains its previous web bundle until the replacement is verified.

An interrupted web-asset request releases the upload promptly. The ESP32-S3 restores the previous pages, and a competing or out-of-order request leaves the active upload intact.

Firmware upload also releases immediately if the connection drops mid-request. Competing chunks leave the active update intact. A retried chunk can confirm reboot only if that chunk committed the firmware.

Calibration rejects stale I²C ADC readings. A failed recapture clears the affected unsaved battery-divider, load-cell, pressure, fuel-flow, or current result. Changing analog torque scale alone preserves the saved zero point. The oil NTC card uses the measured ADC count to indicate when a reading is outside the saved curve.

Timed calibration captures wait for fresh telemetry frames. If the stream stalls, the capture fails and can be retried once live readings return.

Flame noise calibration uses readings taken in the selected igniter state. If the Tools igniter test ends before enough valid readings arrive, capture again after reviewing its duration.

Pump-assisted oil calibration stops refreshing pump demand when live readings stall and returns to the first step. Restart the wizard once readings return.

Pressure calibration can use any configured pump offered in the pump picker. The choice is temporary, so the same pump can serve several sensors as the test plumbing is changed. Sensor-only calibration remains available. The oil pump minimum-output wizard retains its own oil-pump requirement.

The shared calibration pump controls check live pump demand after Run and Stop. If Stop cannot be confirmed, baseline capture and calibration saves wait until a retry confirms zero demand. Analog fuel, oil, scavenge and general flow sensors can use the same pump picker.

Pump commands from the shared picker are tied to the connected ECU and its current boot. Switching ECUs ends the browser’s refreshes and requires reloading Calibration before running a pump.

Pulse flow sensors use the difference between two ECU pulse counts and the collected volume to calculate pulses per litre. The pump picker is optional.

Pulse and named analog flow calibration saves are tied to the ECU and boot that supplied the readings. The same check also applies to named auxiliary analog pressure sensors.

Throttle and idle calibration require two fresh captures and discard them if the ECU restarts. Reopening the page shows the saved range without applying the endpoint margins again.

Fuel pressure, P1, P2, and analog fuel-flow calibration require fresh telemetry for each measured point and discard unsaved points on restart. P1 and P2 still accept entered factory specifications.

Oil-pressure calibration clears unsaved points and returns to the first step when the ECU restarts, including when a fitted sensor curve is already on the review step.

Calibration requires reloading the page after switching ECUs. Settings, hardware, and combined calibration saves carry the identity of the ECU whose setup was opened.

Hardware, Controllers, Sequence, and System also bind their drafts to the ECU they loaded. A rejected save keeps the draft and asks the operator to reload before working on the newly connected ECU.

Log saves only the edited recording settings and binds them to the ECU that supplied Session Data. Reopening the tab or receiving a save rejection keeps the unsaved edits.

Fuel-metering calibration cancels the manual output refresh, sweep, or restart test when live readings stall. Calibration demand expires after three seconds without a refresh. The separate Minimum Fuel Output Test keeps its configured duration.

Sequence, Controllers, System, and Calibration save edits that span Hardware and Settings together. The ECU reboots once after a successful combined save.

Sequence uses **Save** for both types of edit. On ESP32-S3, settings-only changes display **Saved** once the ECU confirms they are active. Sequence structure changes reboot automatically. Startup also shows the oil-pressure shutdown threshold and confirmation time when that protection monitors startup.

**Wait for Complete Stop** can use N1, N2, both fitted shafts, or a fixed delay before cutting main oil. Existing setups use N1 by default.

The afterburner confirmation timeout starts at the first fuel command and is independent of the unverified timed delay. Custom light-up sequences with delays after fuel starts use part of that timeout before the verification card runs.

Afterburner enters Running after all light-up cards finish. If confirmed flame feedback or the selected EGT input is lost before then, the ECU cuts afterburner fuel and records the active card. The configured running flame-loss delay applies once Afterburner is Running.

Automatic afterburner firing requires a fresh trigger assertion. Returning arm permission or recovering a lost signal while the trigger is held requires a healthy release before another fire request.

Edit the afterburner confirmation timeout, stabilization hold, and stabilization temperature ceiling in Controllers. Sequence shows the timing and links to those settings.

The shared oil-pressure limit has one editing location in Controllers. Accelerate to Idle and Final Startup Checks show the current value and link to it. Named oil-pressure controllers still have their own protection thresholds.

Hardware shows the saved analog flame threshold, hysteresis, and active state. Edit them in Calibration, with enough voltage precision to preserve every ADC count.

Edit a custom gate's condition and timer together using its **Edit** button. Sequence shows the saved threshold, hold time, and deadline. An empty threshold requires an entry, and a reading that qualifies after the deadline follows the configured timeout action.

Startup-only oil and fuel pressure protections no longer request reduced power in Running if their feedback drops out. Oil-pressure controllers still monitor the feedback they need to regulate their pumps.

If a saved engine file is missing its Hardware or Settings section, the ECU blocks START and keeps the file available for export. System downloads a damaged or incomplete file byte for byte as a recovery copy. Restore a complete engine file or reset the configuration in System. Appearance changes cannot rewrite a file awaiting repair.

The ECU preserves complete Settings files byte for byte at boot and writes them only when a repair or save is needed.

If a save replaces the engine file during a backup or a Classic ESP32 Settings read, the browser retries against the current file. Each successful response contains bytes from one version.

The Dashboard commissioning checklist now records hardware-only calibration saves, mixed Controllers saves, and accepted actuator-test commands. A successful engine-file restore or factory reset clears marks for the previous setup.

Restore a hidden commissioning checklist from **Dashboard → Edit cards**. Hiding or showing the checklist preserves its progress.

Click a Dashboard card to reveal its links or details. Click a collapsed Hardware device card or its Edit button to open the editor. Advanced output settings stay open when edited, and the fault override identifies the power-on demand it uses. Shutdown & Protection uses the selected accent on Controllers.

The compact controls show an unsaved-changes message when the page has an edited draft. Calibration shares the Dashboard’s pressure and temperature units and uses consistent ambient and reference capture rows across pressure sensors. Use the pump checkbox to show the picker when a compatible pump is configured.

The pump checkbox sits below the capture controls. If the ambient reference or known pressure changes after capture on Fuel Pressure, P1, or P2, capture the changed point again before saving. Log uses the same confirmation dialog as other pages for clearing events and deleting session files.

Calibration keeps units and the fitted-device picker together at the top. The minimum fuel-metering wizard appears when a proportional Main Fuel output is fitted. Hardware marks the Fault LED card when its settings have changed and explains why current sensing uses ADC1 GPIOs.

Hardware and Settings reads use the connected ECU's configuration, including when two ECUs use the same access-point address.

Commissioning progress is saved in the browser for each ECU. Earlier progress marks shared by all ECUs at one address are no longer shown.

An afterburner-only fault leaves the selected main-engine relight igniter available. If the ECU cannot restore its configuration backup, it retains the backup and blocks startup.

Use Setup Tool 0.8.0 or newer with the matching firmware and web package.
